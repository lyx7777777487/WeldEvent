# 焊缝质检流程实例 (含完整确认沟通)

> 本文档以 T 型角焊缝为例, 演示从"用户上传图"到"出具质检结论"的完整交互。
> 核心原则: **方案不直接执行, 必须经逐项确认 -> 弹窗选择 -> 最终拍板**。
> 核心设计: 先看图(阶段0) -> 按图片×需求五档分级路由 -> 简单直接答, 复杂才编排工作流。
> 依据真实代码: request_confirmation(阻塞弹窗+选项) / approval-card(架构级卡片) /
> system prompt 渐进式方案设计("禁止一次性输出完整方案, 每个关键决策点停下来确认")。

---

## 交互机制 (代码已实现)

系统有三种确认形态, 按场景选用:

| 形态 | 触发方式 | 前端表现 | 何时用 |
|------|---------|---------|--------|
| **文字追问** | LLM 直接在回复里问 | 普通对话气泡, 用户打字回 | 需要用户补充信息(材质/板厚/标准), 非选择题 |
| **弹窗选项卡** | `request_confirmation(question, options)` | 确认卡片 + 2-4 按钮 + 自定义输入框 | 需要用户在几条路线里选(返修/让步/报废), 工具阻塞等用户点 |
| **架构确认门** | launch_workflow 触发 ApprovalGate | approval-card 卡片(方案摘要+确认/拒绝) | 不可逆操作前, 架构自动拦截, 不依赖 LLM 自觉 |

**关键**: `request_confirmation` 会阻塞 ReAct 循环, 用户点选项后 `user_selection` 传回 LLM 才继续。
每轮只问一个问题 (工具约束)。

## 分级路由决策 (用户上传图后的第一步分流)

> **核心思想**: 不是所有图片都值得跑工作流。
> agent 拿到图后, 先做"图像理解(阶段0)", 再综合**图片复杂度 × 用户需求深度**决定走哪条路。
> 简单的用模型直接答(秒级, 零成本), 复杂的才编排工作流(留痕, 可审计)。
> 现有 system prompt 只有"问答 vs 执行"二档, 这里扩展为多档分级。

### 分流维度 (两个轴交叉)

**轴 1: 图片复杂度** (agent 看图后判断)
- 简单: 单焊缝、无遮挡、缺陷明显或明显无缺陷
- 中等: 多焊缝/有疑似缺陷/边界情况
- 复杂: 多焊缝交叉、需精确测量、缺陷需判定等级

**轴 2: 用户需求深度** (用户说的话判断)
- 看一眼: "这图行不行""有没有明显问题"
- 要结论: "帮我质检""这个合格吗"
- 要报告: "出份质检报告""留档"

### 五档分级路由 (图片×需求 决定走哪条)

| 档位 | 触发条件 | 走什么 | 延迟 | 留痕 | 典型场景 |
|------|---------|--------|------|------|---------|
| **L0 即问即答** | 图片简单 + "看一眼" | 只调 analyze_image, 模型直接答 | 秒级 | 无 | "这焊缝有没有明显气孔?" |
| **L1 门禁预判** | 图片任意 + "行不行" | 跑 IQA 规则层, 按置信度答 | 秒级 | WeldMap image/quality | "这图能不能用来判?" |
| **L2 轻量质检** | 图片简单 + "要结论" | IQA + analyze_image 综合, 不编排工作流 | 秒-十秒 | WeldMap | "这个合格吗" (单焊缝) |
| **L3 标准质检** | 图片中等/复杂 + "要结论" | design+launch 完整工作流 (IQA->MEA->RDA) | 分钟 | WeldMap全域+DecisionRecord | "帮我质检" (T型角焊缝) |
| **L4 正式报告** | 任意 + "要报告" | L3全流程 + 人工复核 + 导出报告 | 分钟+ | 全域+审计 | "出份质检报告留档" |

### 分流决策树

```
用户上传图 + 说需求
  │
  ├─ "看一眼/有没有明显问题" (需求=看一眼)
  │   └─ analyze_image 看图 ──明显无缺陷──> L0 即问即答 (一句话答)
  │                       └─有疑似/不确定──> 升级到 L1/L2
  │
  ├─ "这图行不行/能不能用" (需求=看一眼, 关注图片本身)
  │   └─ L1 门禁预判 (跑 IQA 规则层, 置信度答)
  │
  ├─ "合格吗/帮我质检" (需求=要结论)
  │   └─ analyze_image 看图 ──单焊缝无歧义──> L2 轻量质检 (不编排工作流)
  │                       └─T型/多焊缝/需测量──> L3 标准质检 (编排工作流)
  │
  └─ "出质检报告/留档" (需求=要报告)
      └─ L4 正式报告 (完整工作流 + 人工复核 + 审计)
```

### 关键设计原则

1. **能轻不重**: L0 能答的不上 L1, L2 能答的不编排工作流
   - 理由: 工作流有 Temporal 开销 + 确认门往返, 简单场景用它是浪费
2. **看图后才能定档**: 不能只看用户文字就定档
   - 用户说"质检", 但图可能简单到不用工作流; 也可能复杂到必须工作流
   - 所以阶段0(看图) 必须在分级之前
3. **可升级不可降级**: L0 发现不确定 -> 升级 L2/L3; 但 L3 跑完达标不再退回 L0
4. **L0/L1 不留痕是特性**: "看一眼"类问题不产生质检结论, 不该进审计
   - L2+ 才写 WeldMap, 因为这才算"做了质检"
5. **用户可强制升级**: 用户说"虽然看起来没问题, 但给我出个报告" -> 强制 L4

### 现有代码的 gap

| 能力 | 现状 | 分级需要 |
|------|------|---------|
| 意图二分类(问答/执行) | ✓ system prompt 有 | 需扩展为五档 |
| "该不该用工作流"判断 | ✓ design_workflow 有"不对纯问答用" | 需加 L0/L2 的中间判断 |
| IQA 规则层单独跑 | ✓ 真实 | L1 门禁预判可直接用 |
| analyze_image 直接答 | ✓ 真实 | L0/L2 直接用, 不经工作流 |
| 分级路由逻辑 | ✗ 缺 | agent 看图后决定走 L0-L4 的判断逻辑未固化 |
| "看一眼"不留痕 | ✗ 缺 | L0/L1 跳过 WeldMap 写入的逻辑 |

## 场景: T 型角焊缝标准质检 (L3 档 - 完整流程示例)

> 本场景演示 L3 标准质检档: 图片中等/复杂 + 用户要结论("帮我质检")。
> 走完整工作流 (IQA->MEA->RDA), 含阶段0看图分级 -> 确认沟通 -> 执行 -> 返修。
> L0/L1/L2 轻量档见文末"其他档位示例"。

### 阶段 0: 图像理解与分级 (用户说"质检这张图"的第一步)

> 用户上传图说"帮我质检", agent 第一反应不是问材质板厚, 也不是直接编排工作流,
> 而是: (1) 先看图 (2) 三路检索聚合 (3) 判断该走哪档 (4) 带认知去问前提。
> 若判断为 L0/L2 (简单图), 直接答不编排工作流; 判断为 L3 (T型/需测量), 才走下面流程。

**第 0 轮**



> 接阶段 0: agent 已看完图并给出初步认知, 现在等用户回复 3 个前提。

**第 1 轮**
> **用户**: Q345R, 12mm, 用你建议的 B 级

*(用户采纳了 agent 阶段0 的 B 级建议。若用户说"用 C 级", agent 重新算阈值。)*

### 阶段 2: 标准数字化 + 阈值确认 (弹窗)

**第 2 轮**
> **Agent**: 收到 Q345R/12mm/B 级。我把判定基准数字化, 请确认:
>
> | 参数 | 值 | 来源 |
> |------|-----|------|
> | 母材 | Q345R | 用户提供 |
> | 板厚 | 12mm | 用户提供 |
> | 焊脚最小尺寸 K_min | 8.4mm (=0.7×12) | GB/T 19418 角焊缝构造要求 |
> | 咬边限值 | ≤0.5mm | GB/T 19418 B 级 |
> | 裂纹/未熔合 | 不允许 | GB/T 19418 B 级 |
> | 气孔 | 限量内 | B 级表面缺陷限制 |
>
> 判定逻辑:
> - 焊脚 < 8.4mm -> 不合格 (硬指标)
> - 咬边 > 0.5mm -> 需复核
> - 发现裂纹/未熔合 -> 直接不合格

*(工具: search_standards 查 GB/T19418 条款, 把文字标准转成可执行阈值)*
*(这是"标准数字化", system prompt 要求"标准不清就先整理标准"。)*

**第 3 轮** (弹窗确认阈值, 防止 Agent 瞎设阈值)

> **Agent** 调 `request_confirmation`:
>
> ┌─────────────────────────────────────┐
> │ ⚠️ 确认判定阈值                       │
> │                                       │
> │ 上述判定基准是否正确?               │
> │ 特别确认: 焊脚最小尺寸 8.4mm 是否    │
> │ 符合你们的验收要求?                  │

> │  [阈值正确, 开始设计]  [我来调整阈值] │
> │  [用更严格的 A 级]                    │

*(工具: request_confirmation(question, options=["阈值正确,开始设计","我来调整阈值","用更严格的A级"]))*
*(阻塞等待用户点选。为什么用弹窗: 阈值是关键判定依据, 必须用户显式拍板, 不能 LLM 默认。)*

## 何时用文字追问 vs 弹窗 (设计规则)

| 场景 | 用什么 | 原因 |
|------|--------|------|
| 补充开放信息(材质/板厚) | 文字追问 | 不是选择题, 用户自由输入 |
| 确认判定阈值是否正确 | 弹窗(选项) | 关键判定依据, 需显式拍板 |
| 逐节点确认方案 | 弹窗(逐个) | 每节点是独立决策点, 逐个确认 |
| 最终启动工作流 | 架构确认门 | 不可逆, 架构拦截留痕 |
| 处理路线(返修/让步/报废) | 弹窗(选项) | 多路线选择, 不可逆走 T2 |
| 简单查询(进度/状态) | 文字直接答 | 无需确认 |

**规则**: 能查到的直接查(不问); 关键决策点逐个弹窗确认(不跳); 不可逆操作走架构门(不靠 LLM 自觉)。

## 其他档位示例 (L0/L1/L2 轻量级 - 不编排工作流)

### L0 即问即答 (图片简单 + "看一眼")

> **用户**: (上传单道平焊缝图) 这焊缝有没有明显气孔?

> **Agent** 调 analyze_image(question="是否有明显气孔"):
> 没有明显气孔, 焊缝成形平整。无明显表面缺陷。

*(到此结束。不编排工作流, 不写 WeldMap, 不问材质板厚。因为用户只是"看一眼"。)*

### L1 门禁预判 (任意图 + "能不能用")

> **用户**: (上传图) 这图能不能用来判质检?

> **Agent** 调 IQA 规则层:
> | 检查 | 结果 |
> |------|------|
> | 分辨率 | 2448×2048 ✓ |
> | 对焦 | 方差 142 ✓ |
> | 置信度 | 0.91 |
>
> 能用, 照片质量达标, 可以进入判定。
> 要不要我继续做质检? (升级到 L2/L3)

*(只跑 IQA 门禁, 不编排工作流。若用户说"继续质检", 升级到 L2/L3。)*

### L2 轻量质检 (图片简单 + "要结论" - 不编排工作流)

> **用户**: (上传单道平焊缝图) 这个合格吗?

> **Agent**: 先看图, 判断这是单道平焊缝, 无需精确测量(非角焊缝)。
> 调 analyze_image + IQA 综合判断:
> 焊缝成形良好, 无咬边/气孔/裂纹, 照片质量达标(置信度0.92)。
> **初步判断: 合格**。
> 注: 这是轻量判断, 未做精确几何测量。如需正式报告(留档), 我可以出完整报告(升级 L4)。

*(单焊缝无歧义, 不编排工作流。但诚实告知"轻量判断, 未精确测量", 给用户升级选项。)*
