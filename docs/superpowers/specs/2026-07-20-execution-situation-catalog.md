# WeldEvent 执行期情况流穷举清单

> 目的：把工作流执行过程中**可能出现的所有情况流**穷举出来，供逐条补充与确认，最后再选技术适配。
> 范围：执行期（L2 调度 + L3 Activity）。排除"人主动发起介入的操作流程"（如审查卡片、override 的操作步骤），但"系统请求人工介入"作为出口会标注。
> 每条情况只给：**触发条件 / 影响 / 当前处理倾向**，不绑定具体技术。
> 标注：✅ 现有两文档已覆盖 · ➖ 部分覆盖 · ❓待补充确认 · 🆕 本次新增细分

#### R.4.1 `pydantic/pydantic-ai-harness`（官方 [P] 源 · 最相关）

**研究结论**：这是 IMPLEMENTATION_REPORT 中 `[P]` Pydonic AI Harness 的**真正出处**（之前文档把它当抽象来源，实际是 pydantic 官方 capability 库）。其 `DynamicWorkflow` 是前沿工作流编排模式，直接可借鉴。

| # | 机制 | 仓库实现 | 借鉴到 WeldEvent | 对应 |
|---|---|---|---|---|
| R4.1 | **单脚本编排子 agent** | 模型写一个 Python 脚本，每个子 agent 是 async 函数，整棵树一次 tool call 跑完 | 替代"逐个委派"：一次工具调用完成 fan-out+chain，**中间结果不回灌编排器上下文**（解决上下文膨胀） | 升级 `[31][35]` ReWOO/Orchestrator |

| R4.5 | **能力即 capability+hooks** | harness = 工具+生命周期 hooks+指令+模型设置的打包，不改框架即扩展 | 8 模块/智能层都应做成 capability 插件而非改核心 | 架构原则 |
