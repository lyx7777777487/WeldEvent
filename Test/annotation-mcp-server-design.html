鉴权链路

请求 → nginx (8079) │ ├─ /api/auth/* → 直达 auth-server (放行) │ └─ /api/* → auth_request /api/auth/verify │ ├─ 提取 JWT (Cookie/Header) ├─ 验签 + 查 url_permission 表 ├─ 通过 → 返回 X-User-Id header └─ 失败 → 401/403 │ ├─ /api/annotation/* → proxy_pass → annotation-server :8081 └─ /api/(users|roles|...) → proxy_pass → auth-server :8082

RBAC 基于 url_permission 表，用 AntPathMatcher 匹配 URL 模式 + HTTP 方法，关联 permission code。nginx 通过 auth_request 模块实现统一鉴权，后端服务无需感知 Spring Security。

2. MCP Server 方案设计

2.1 要不要做

结论：要。

将 annotation-server 的核心 API 封装为 MCP Tools，让 DeerFlow 等 AI Agent 能通过自然语言操控标注平台。例如："查一下数据集 123 的标注进度"、"把未完成的任务重新分配"。

原则：不是把整个 annotation-server 搬过去，只挑几个核心 Tool，保持 MCP Server 轻量。只做调用转发，不内嵌业务逻辑。

2.2 走不走 nginx

决策
MCP Server 必须走 nginx，和浏览器客户端完全一致。
方案鉴权方式问题
直接调 8081 UserContextFilter 只解码 JWT payload，不验签 任何伪造的 JWT 都能通过，等同于裸奔
走 nginx 8079 完整 auth_request 链路：验签 + url_permission 鉴权 无。和浏览器请求走同一套安全机制
优点
Agent 用户就是一个普通业务账号（如 agent-bot），通过 url_permission 表精确控制它可调用的 API，权限、审计、限流全部复用现有链路。

2.3 传输协议：SSE 还是 Streamable HTTP

决策：Streamable HTTP
每次 Tool 调用是独立的 HTTP POST 请求，每次都走完整的 nginx → auth_request → verify 链路。
Token 过期 → 401，权限不足 → 403。和浏览器请求一模一样，零额外 nginx 配置。
SSEStreamable HTTP
连接模型 一条长连接 GET /sse 每次调用独立 POST
auth_request 只建连时触发一次 每次请求都触发
token 过期后 连接仍存活，无感知 下次请求直接 401
nginx 配置 需额外配 proxy_buffering off + 长超时 零改动
权限变更生效 下次重连才生效 即时生效

2.4 暴露哪些 API 为 MCP Tool

从 annotation-server 的 16 个端点中选取 8 个核心操作：

Tool 名称对应 API用途
list_datasetsGET /api/datasets分页列出数据集
get_datasetGET /api/datasets/{id} + GET /api/datasets/{id}/images数据集详情 + 图片列表
create_jobPOST /api/jobs创建标注作业
list_jobsGET /api/datasets/{id}/jobs按数据集列作业
get_jobGET /api/jobs/{id}作业详情 + 进度
list_tasksGET /api/jobs/{id}/tasks按作业列子任务
create_taskPOST /api/tasks创建标注任务
trigger_aiPOST /api/agent/trigger触发 AI 标注
assign_taskPUT /api/tasks/{taskId}/assign分配标注员

不包括 Agent 内部调用（start-task、report-progress、manual-annotation），这些是 agent-service 和 annotation-server 之间的内部协议，不应暴露给外部 Agent。

2.5 技术选型

项选择理由
语言Node.js + TypeScriptMCP Server 只做 HTTP 转发，不需要 Spring Boot 的笨重；MCP TypeScript SDK 生态成熟，和 agent-service 技术栈统一
传输Streamable HTTP见 2.3 节分析
部署位置172.16.11.11和其他服务同一机器，内网延迟最低
认证Streamable HTTP 每次请求带 JWTAgent 用户用自己身份登录，和浏览器走同一套 auth_request 链路，无需固定 service account
扩展性无状态，支持多实例Streamable HTTP stateless 模式下每个请求独立，MCP Server 不持有会话状态。流量上来时启动多实例，nginx upstream 负载均衡即可

问题结论
MCP Server 是否走 nginx是，和浏览器客户端统一走 auth_request 鉴权
MCP Server 本身要不要鉴权不需要。通过 nginx /api/mcp location 访问（不配 auth_request），监听 127.0.0.1，无状态无密钥
鉴权在哪里做MCP Server 透传 Agent 的 JWT 到 nginx :8079 /api/annotation/*，在 nginx auth_request 层统一鉴权
传输协议Streamable HTTP，每次请求独立鉴权

5. 讨论过程中排除的方案

方案结论排除原因
直接调 annotation-server 8081 不采用 UserContextFilter 不验 JWT 签名，安全隐患
SSE 传输 不采用 长连接模型与 auth_request 不兼容，token 过期无感知
